## Minor (nice to have)

- **lib/agent-tools.ts:648 (`get_reference_data`)** -- If `suppliers.json` or `warehouses.json` contains valid JSON that parses to `null` (e.g., the file literally contains the text `null`), then `null.suppliers` throws a `TypeError` inside the try/catch. The error is caught and returned as `{ error: "Failed to read reference data: Cannot read properties of null (reading 'suppliers')" }`, which is misleading -- it implies a file-read failure rather than an unexpected file format. Triggered by someone manually writing `null` into one of these JSON files. Fix: add a guard like `if (!suppliers || typeof suppliers !== 'object') return { error: "suppliers.json has unexpected format" }` before accessing `.suppliers`. Very unlikely in practice since these files are generated by the sync toolchain.

- **lib/agent-tools.ts:654-675 (`run_sync_diff`)** -- The tool checks for the existence of `inventory.json` and `inventory-proposed.json` but does not check for `suppliers.json` or `warehouses.json`. If either reference file is missing, `computeDiff` throws (via `safeReadJson`), which is caught by the try/catch and returned as `{ error: "Diff computation failed: Cannot read suppliers (...): ENOENT..." }`. This works correctly but gives a less user-friendly error than an explicit upfront check like `"No suppliers.json found."`. Triggered by running the diff in a fresh environment before reference files are generated. Fix: add `existsSync` checks for `suppliersPath` and `warehousesPath` with targeted error messages, consistent with the existing checks for inventory files.

- **tests/agent-sync-tools.test.ts** -- No test for the `run_sync_diff` scenario where `computeDiff` throws (e.g., malformed JSON in one of the input files). This is listed as an edge case in B005-requirements.md (`run_sync_diff when inventory-proposed.json exists but contains invalid JSON -- returns error from computeDiff()`) but has no corresponding test. The production code handles this correctly via try/catch; this is only a test coverage gap. Fix: add a test that mocks `computeDiff` to throw and asserts the error response contains `"Diff computation failed"`.

- **tests/agent-sync-tools.test.ts** -- No test for `save_proposed_inventory` with `products: 123` (a numeric non-array). This is listed as an edge case in B005-requirements.md. The production code handles it correctly (`!Array.isArray(123)` returns true, so the error path is taken). The existing test for `products: "not an array"` already covers the same code path, so this is purely a documentation-to-test alignment gap. Fix: add a one-liner test `it("rejects when products is a number", ...)` for completeness.

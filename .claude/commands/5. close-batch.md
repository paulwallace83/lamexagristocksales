# /close-batch — Close Out and Merge a Batch

## Description
Run after all refactoring is complete. Handles final verification, documentation updates, and prepares for merge.

## Instructions

### 1. Final Test Run
Run the full test suite before touching any docs. All tests must pass. If any fail, fix them before proceeding.
```
npm test
npx tsc --noEmit
```

### 2. Update Documentation
Work through the Documentation Checklist from `docs/workflow.md`:

- **CLAUDE.md**: Update "Current Sprint Context" — move the batch from "Batch Queue" to "Completed". Update any feature descriptions, key file lists, or capability counts that changed.
- **docs/roadmap.md**: Move the relevant slice from its current section to "Completed" with a version number and highlights.
- **docs/Architecture.md**: If any design decisions changed during this batch, update the architecture to match the actual implementation. Congruency between docs and code is mandatory.
- **LESSONS.md**: Review the retro and review findings — add any new entries for patterns to follow or mistakes to avoid.
- **docs/epics.md**: Update the epic status if this batch completes or advances it.

### 3. Check for Doc Drift
Scan `CLAUDE.md` and `docs/Architecture.md` for any statements that contradict what was actually built. Fix them. Future agents will read these docs and make decisions based on them — they must be accurate.

Run the cross-check:
- `grep -r "AGENTS.md" *.md docs/*.md` — should return zero results
- Check that `CLAUDE.md` "Batch Queue" table reflects the updated status
- Check that `CLAUDE.md` key files sections reference any new or renamed files

### 4. Clean Up
- Verify no TODO comments reference this batch's ID without a resolution
- If any items were deferred during `/refactor`, confirm `docs/reviews/{batch-id}-deferred.md` exists
- Confirm no Critical review findings remain open

### 5. Summary
Print a brief summary:
- What was built in this batch
- What documentation was updated
- Any deferred items (TODOs, items for future batches)
- What the next batch should be and any context the next agent needs

## Rules
- Never close a batch with failing tests
- Never close a batch with unresolved Critical review findings
- Never leave `Architecture.md` contradicting the actual implementation
- Always update "Current Sprint Context" in `CLAUDE.md` — the next agent depends on it
- If deferred items exist, verify they have TODO comments in code AND entries in the deferred findings doc

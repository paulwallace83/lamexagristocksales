# /retro — Post-Implementation Retrospective

## Description
Run immediately after implementation is complete, BEFORE compacting context. This captures the implementing agent's honest self-assessment while it still has full memory of every decision and shortcut.

## Instructions
Review all code you created or modified in this batch. For each file:

1. **Confidence Rating (1-10)** — how confident are you this code is correct?
2. **Uncertainty** — what are you NOT fully confident about?
3. **Refactoring** — what would improve quality if you had more time?
4. **Shortcuts** — what corners did you cut?
5. **Edge Cases** — what scenarios did you not handle?

Be brutally honest. It is better to catch issues now than in review.

### Lamex-Specific Checks
For each file also consider:
- **Sync survival:** Does any new data use lot IDs instead of lot numbers? Will it survive a weekly sync?
- **Data privacy:** Could any output leak customer names, pricing, or sensitive ERP fields?
- **Client/server boundary:** Is `better-sqlite3` safely on the server side only?
- **Path safety:** Are all user-derived path segments sanitised + resolved + prefix-checked?

## Output
Save findings to `docs/reviews/{batch-id}-retro.md` using this format:

```markdown
# Retrospective — {Batch ID}

## Summary
(2-3 sentence overall assessment)

## File-by-File Review

### {filename}
- **Confidence:** X/10
- **Uncertainties:** ...
- **Suggested Refactoring:** ...
- **Shortcuts Taken:** ...
- **Unhandled Edge Cases:** ...

## Items Needing Immediate Attention
(List anything rated below 7)

## Items for Future Batches
(Things that aren't urgent but should be tracked)

## LESSONS.md Candidates
(Any new patterns, mistakes, or non-obvious decisions worth capturing)
```

## Rules
- Do NOT compact context before running this
- Do NOT skip files — review every file touched
- Anything rated below 7 must be flagged for immediate fixing
- Be specific — "could be better" is not useful, "the error handler on line 42 swallows the original error message" is useful
- Always check for data privacy violations — customer names and pricing are the highest-severity leak in this project
